主路径流程

SINGLE_AGENT_REVIEW 会跳过 SE、AE 初筛和多审稿人并行，只保留必要预处理和一个综合审稿节点。

mode = SINGLE_AGENT_REVIEW
doc_parse文档解析

把用户上传的 PDF、Markdown 或 TeX 解析成统一的 ParsedPaper。

  • 输入：paper_path
  • 输出：parsed_paper、paper_content
实现位置src/graphs/nodes/doc_parse_node.py
src/infra/parser.py
parse_ok进入内容检查。
parse_failed进入 parse_fail_output，再走最终渲染。
content_check论文有效性判断

用 LLM 判断上传内容是否像一篇学术论文，避免把任意文件送进审稿流程。

  • 输入：paper_content
  • 输出：intent、content_check
Promptprompts/content_check.md
模型路由configs/llm.yaml
VALID_PAPER继续加载 venue 信息。
not_paper进入 invalid_file，再走最终渲染。
journal_req_collector目标 venue 加载

根据 venue_domain、venue_collection、venue_code 读取本地 venue md。

  • 输出官方要求：journal_requirements
  • 输出智能体画像：venue_profile
数据来源venues/**/*.md
加载器src/core/venues.py
field_analyst领域分析

判断论文领域、研究范式、潜在审稿关注点，并准备审稿人配置。

  • 输入：论文内容 + venue profile
  • 输出：field_analysis、field_info、reviewer_config
Promptprompts/field_analyst.md
分流点这里进入 single_reviewer
single_reviewer综合审稿

一个 Agent 同时扮演综合审稿人，直接给出主要问题、次要问题、问题列表、分数和最终建议。

  • 输入：parsed_paper、journal_requirements、venue_profile、field_info
  • 输出：reviewer_reports、final_decision、decision_letter
Promptprompts/single_reviewer.md
节点文件src/graphs/nodes/single_reviewer_node.py
final_artifact_render报告渲染

把上游结构化结果渲染成最终 Markdown 报告，并准备后续可扩展的 tex/pdf 产物。

  • 输出：final_report_md
  • 输出：rendered_artifacts
落盘位置data/runs/<run_id>/final_report.md

state 是怎么变厚的

LangGraph 节点之间传递的不是 tensor，而是一个不断增加字段的 GlobalState。

src/graphs/state.py

一开始就有

run_idpaper_pathreview_modeoutput_languagevenue_code

解析后增加

parsed_paperpaper_contentparse_error

审稿后增加

reviewer_reportsfinal_decisiondecision_letterfinal_report_md

prompt 和模型如何进入节点

节点不直接写死供应商。节点只选择 prompt，prompt 里写模型别名，Router 再查真实供应商。

single_reviewer_node
  → get_review_nodes()
  → ReviewNodes.single_reviewer(...)
  → PromptRepository.render("single_reviewer", context)
  → prompts/single_reviewer.md
  → model: "review-main-model"
  → configs/llm.yaml
  → xunfeid / xopqwen36v35b
  → .env 里的 LLM_XUNFEI_BASE_URL + LLM_XUNFEI_API_KEY

最终会看到哪些文件

每跑一篇论文，service 层都会把 LangGraph 的结果写进一个独立 run 目录。

data/runs/<run_id>/
final_report.md最终给作者看的审稿报告。
single_reviewer.json单 Agent 结构化审稿输出。
stage_outputs.json每个节点的中间结果汇总。
diagnostics.json / llm_calls.jsonl诊断信息和 LLM 调用摘要。
